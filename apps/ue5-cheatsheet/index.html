◎ Editor Layout & Core Panels

Key Panels

  • Content Browser — Asset library; organise with folders, filters, collections. Supports drag-and-drop into viewport.
  • Outliner — Hierarchical list of all actors in current level. Right-click for grouping, folders, visibility toggles.
  • Details Panel — Property inspector for selected actor/component. Search bar filters properties.
  • World Settings — Level-wide settings: GameMode override, Lightmass, World Partition, Kill-Z, gravity.
  • Modes Panel — Switch between Place, Paint, Landscape, Foliage, Geometry editing modes.
  • Output Log — Runtime logs, warnings, errors. Essential for debugging.

Project Structure

  • /Content — All game assets (meshes, textures, Blueprints, maps)
  • /Config — .ini config files (DefaultEngine, DefaultGame, DefaultInput)
  • /Source — C++ source files (only in C++ projects)
  • /Plugins — Project-level plugins
  • /Saved — Autosaves, logs, screenshots, local configs
  • /Intermediate — Build artifacts (safe to delete)
  • /Binaries — Compiled binaries
  • .uproject — Project descriptor file
  • .uasset — Binary asset format
  • .umap — Level / map file

◆ Actors & Components

Core Actor Types

  • Actor — Base class; any object placeable in a level
  • Pawn — Actor that can be "possessed" by a Controller
  • Character — Pawn with CharacterMovementComponent (walk, jump, swim, fly)
  • PlayerController — Represents human player input/logic
  • AIController — Controls AI-driven Pawns
  • GameMode — Server-authoritative rules: default Pawn, HUD class, match state
  • GameState — Replicated game-wide state (score, timer)
  • PlayerState — Replicated per-player state (name, score)
  • HUD — Legacy canvas drawing class (prefer UMG)

Common Components

  • StaticMeshComponent — Renders a static mesh
  • SkeletalMeshComponent — Renders a skeletal mesh with animations
  • CameraComponent — Camera viewpoint
  • SpringArmComponent — Camera boom with collision/lag
  • CapsuleComponent — Common collision for characters
  • BoxComponent / SphereComponent — Overlap & trigger volumes
  • AudioComponent — Plays sounds spatially
  • PointLightComponent — Attaches a light to an actor
  • NiagaraComponent — Attaches a VFX system
  • WidgetComponent — Renders UMG in 3D world space
  • SceneComponent — Transform-only; used as attachment roots

Actor Lifecycle

  • Constructor — Set defaults (CDO). No world context!
  • PostInitializeComponents — All components initialized
  • BeginPlay — Level started, actor is in world
  • Tick(DeltaTime) — Called every frame (can disable)
  • EndPlay — Actor removed or level unloaded
  • Destroyed — Final cleanup
  • Spawn flow: SpawnActor → Constructor → PostInit → BeginPlay
  • Tip: Use SetActorTickEnabled(false) for actors that don't need per-frame updates
⬡ Blueprints Visual Scripting

Blueprint Types

  • Actor Blueprint — Blueprint placed in levels (most common)
  • Level Blueprint — Per-level scripting; avoid for reusability
  • Widget Blueprint — UMG UI layout & logic
  • Animation Blueprint — State machines for skeletal meshes
  • GameMode Blueprint — Match rules, default classes
  • Blueprint Interface — Define callable functions across unrelated BPs
  • Blueprint Function Library — Static utility functions
  • Blueprint Macro Library — Reusable node graphs (inlined at compile)
  • Struct — Custom data structures (like C structs)
  • Enum — Named constant lists

Essential Nodes

  • BeginPlay — Fires once when actor starts
  • Tick — Fires every frame (use sparingly!)
  • Branch — If/else (bool input)
  • Switch on Int/String/Enum — Multi-way branching
  • ForEachLoop — Iterate arrays
  • Timeline — Animate values over time with curves
  • Delay — Wait N seconds (latent node)
  • Gate / FlipFlop / DoOnce — Flow control
  • SpawnActor — Instantiate actor at runtime
  • Cast To — Type check + downcast (avoid in Tick!)
  • Get / Set — Variable access
  • Custom Event — Reusable event entry point
  • Event Dispatcher — Observer pattern / delegates
  • Interface Message — Call BP Interface function

Blueprint Best Practices

  • Keep Event Graph clean — move logic into Functions
  • Use Collapsed Graphs or Comments to organise
  • Avoid Cast To in Tick — cache the reference in BeginPlay
  • Prefer Event Dispatchers over direct references for loose coupling
  • Prefer Interfaces over Cast To for polymorphic calls
  • Use Timelines instead of Tick for interpolation
  • Set Replication flags in variable details (Replicated, RepNotify)
  • Mark pure functions as Const
  • Use Data Tables and Data Assets for designer-tweakable data
  • Reparent to C++ base classes for performance-critical code C++

λ C++ Essentials C++

Core Macros

  • UCLASS() — Expose class to UE reflection (before class declaration)
  • UPROPERTY() — Expose variable (EditAnywhere, BlueprintReadWrite, Replicated, etc.)
  • UFUNCTION() — Expose function (BlueprintCallable, Server, Client, NetMulticast)
  • USTRUCT() — Expose struct to reflection
  • UENUM() — Expose enum
  • GENERATED_BODY() — Required inside UCLASS/USTRUCT
  • UPARAM(ref) — Pass by reference to Blueprint

UPROPERTY Specifiers

  • EditAnywhere — Editable in Details panel
  • VisibleAnywhere — Shown but not editable
  • BlueprintReadOnly — Read in BP graph
  • BlueprintReadWrite — Read + write in BP
  • Category = "Name" — Group in Details panel
  • Replicated — Auto-sync to clients
  • ReplicatedUsing = OnRep_Func — Sync + callback
  • Transient — Not serialised/saved
  • SaveGame — Include in save data
  • meta=(ClampMin, ClampMax) — Range limits in editor

Common C++ Patterns

  • GetWorld()->SpawnActor<T>(Class, Transform) — Spawn at runtime
  • Cast<AMyActor>(OtherActor) — Safe downcast
  • FindComponentByClass<T>() — Get component
  • TArray<T> — Dynamic array
  • TMap<K,V> — Hash map
  • TSet<T> — Unique value set
  • FString / FName / FText — String types (FText for UI localisation)
  • UE_LOG(LogTemp, Warning, TEXT("msg %s"), *Str) — Logging
  • check() / ensure() / verify() — Assertions
  • DECLARE_DYNAMIC_MULTICAST_DELEGATE — Event dispatchers from C++
  • CreateDefaultSubobject<T>() — Create component in constructor

Gameplay Framework Classes

  • AGameModeBase — Rules, default pawn, HUD (server only)
  • AGameStateBase — Game-wide replicated state
  • APlayerState — Per-player replicated state
  • APlayerController — Input, camera, HUD ownership
  • APawn / ACharacter — Player/NPC body
  • UGameInstance — Persists across level loads
  • UGameplayStatics — Static helpers (line traces, spawn, play sound)
  • UKismetMathLibrary — BP-exposed math utilities
◐ Materials & Shading

Material Inputs

  • Base Color — Albedo (RGB, 0–1). No lighting info!
  • Metallic — 0 = dielectric, 1 = metal (binary in practice)
  • Roughness — 0 = mirror, 1 = matte
  • Specular — Override Fresnel reflectance (default 0.5)
  • Normal — Tangent-space normal map
  • Emissive Color — Self-illumination (drives Bloom & Lumen)
  • Opacity / Opacity Mask — Transparency (Translucent / Masked blend mode)
  • World Position Offset — Vertex displacement in shader
  • Ambient Occlusion — Cavity shadows (multiplies indirect light)
  • Subsurface Color — For Subsurface shading model (skin, wax)
  • Pixel Depth Offset — Push depth buffer (contact shadows, decal blending)

Shading Models

  • Default Lit — Standard PBR
  • Unlit — No lighting (UI, custom post)
  • Subsurface — Wax, skin, leaves
  • Subsurface Profile — Higher quality skin
  • Clear Coat — Car paint, lacquered wood
  • Two-Sided Foliage — Leaves with backface transmission
  • Hair — Strand-based shading
  • Eye — Specialised eye refraction
  • Cloth — Fabric sheen
  • Thin Translucent — Glass, colored film
  • Strata — UE5.4+ material layering system NEW

Material Tips

  • Always use Material Instances for per-asset variation (cheaper than new materials)
  • Use Material Functions for reusable node subgraphs
  • Use Material Parameter Collections for global values (time of day, wind)
  • Keep instruction count low — check Stats in material editor
  • Use Texture Packing: pack Roughness/Metallic/AO into RGB channels of one texture
  • Use Virtual Textures for large landscapes UE5
  • Masked blend mode is cheaper than Translucent
  • Avoid Translucent where possible — breaks deferred rendering, no Nanite
▲ Nanite UE5

What is Nanite?

  • Virtualised micro-polygon geometry system — renders billions of triangles
  • Automatic LOD — no manual LOD chain needed
  • GPU-driven rendering: visibility buffer, software rasteriser for small triangles
  • Enable per-mesh: Static Mesh → Details → Enable Nanite Support
  • Converts to internal cluster hierarchy at import/build time

Nanite Support & Limits

  • ✅ Supported: Static Meshes, Instanced Static Meshes, foliage, Masked materials (5.4+), World Position Offset (5.4+)
  • ❌ Not supported: Skeletal Meshes, Translucent materials, morph targets
  • Fallback meshes used where Nanite can't render (debug with Nanite Visualization)
  • Best for: hard-surface, organic environments, foliage, rocks, architecture
  • Displacement mapping via Nanite tessellation (5.4+) NEW
  • Nanite streaming — only loads visible clusters from disk
☀ Lumen UE5

Lumen Global Illumination

  • Fully dynamic GI — no lightmap baking required
  • Traced against simplified scene: Mesh Distance Fields + Surface Cache
  • Software ray tracing (default) or Hardware RT (higher quality, more GPU)
  • Enable: Project Settings → Rendering → Global Illumination → Lumen
  • Bounces driven by Emissive materials — lights can come from any surface
  • Multi-bounce indirect lighting updates in real-time

Lumen Reflections

  • Replaces SSR & planar reflections with ray-traced reflections
  • Enable: Project Settings → Rendering → Reflections → Lumen
  • Works off same Surface Cache as GI
  • Quality/performance controlled via PostProcess Volume: Lumen Reflections Quality
  • Hardware RT reflections for mirror-quality surfaces

Lumen Best Practices

  • Keep meshes watertight — gaps cause light leaks
  • Use Mesh Distance Fields (auto-generated for static meshes)
  • Large flat surfaces benefit from Lumen Surface Cache detail
  • Avoid very thin geometry — causes Surface Cache artefacts
  • Use r.Lumen.Visualize console commands for debugging
  • Emissive surfaces need Emissive boost multiplied into material for strong bounce
  • Combine with Virtual Shadow Maps for consistent shadowing
💡 Lighting

Light Types

  • Directional Light — Sun/moon; infinite distance, parallel rays
  • Point Light — Omni-directional (light bulb)
  • Spot Light — Cone-shaped (flashlight, lamp)
  • Rect Light — Area light (TV screen, window); soft shadows
  • Sky Light — Ambient from cubemap or sky; drives IBL
  • Sky Atmosphere — Physically-based sky & aerial perspective
  • Exponential Height Fog — Atmosphere & volumetric fog
  • Volumetric Cloud — Dynamic cloud layer

Shadow Systems

  • Virtual Shadow Maps (VSM) — Default in UE5; per-pixel resolution, works with Nanite UE5
  • Cascaded Shadow Maps (CSM) — Legacy; still useful for mobile
  • Ray-Traced Shadows — Pixel-perfect; requires HW RT
  • Contact Shadows — Screen-space detail shadows (enable in light settings)
  • Distance Field Shadows — Long-distance soft shadows from Directional Light

Post-Process Volume

  • Bloom — Glow from bright areas; Convolution Bloom for cinematic
  • Exposure — Auto or manual; set Min/Max Brightness
  • Tone Mapping — ACES, custom curves
  • Color Grading — Temperature, tint, saturation, LUT
  • Ambient Occlusion — GTAO (default) or SSAO
  • DOF — Cinematic / Gaussian / Circle (Bokeh)
  • Motion Blur — Per-object and camera
  • Screen Space Reflections — Supplement Lumen reflections
  • Chromatic Aberration — Lens fringe
  • Vignette — Darken edges
  • Film Grain — Noise overlay
  • Path Tracing — Reference mode, offline quality UE5
✦ Niagara VFX

Niagara Architecture

  • System — Container holding one or more Emitters
  • Emitter — Individual particle source (spawns, updates, renders)
  • Module — Building block: a chunk of logic (position, velocity, color)
  • Stages: System Spawn/Update → Emitter Spawn/Update → Particle Spawn/Update → Render
  • Parameters: System, Emitter, Particle, User namespace scoping
  • GPU Sim available for millions of particles

Common Modules

  • Initialize Particle — Set lifetime, mass, sprite size, color
  • Add Velocity — Launch direction & speed
  • Gravity Force — World-space gravity
  • Curl Noise Force — Organic swirling motion
  • Drag — Air resistance
  • Scale Color / Size Over Life — Fade/grow/shrink curves
  • Collision — Scene depth, distance field, or analytic collision
  • Spawn Rate / Burst — Emission control
  • Mesh Renderer — Render meshes instead of sprites
  • Ribbon Renderer — Trails (sword swipes, smoke)
♺ Animation

Animation Assets

  • Skeleton — Bone hierarchy (shared across meshes)
  • Skeletal Mesh — Mesh bound to skeleton
  • Animation Sequence — Single animation clip
  • Animation Montage — Composite: sections, notifies, blending
  • Blend Space (1D / 2D) — Blend clips by input axes (speed, direction)
  • Animation Blueprint (ABP) — State machine + logic
  • Anim Notifies — Events at specific frames (footstep, VFX, sound)
  • Control Rig — Procedural runtime rigging & IK UE5
  • IK Rig / IK Retargeter — Retarget animations across skeletons UE5

State Machine Basics

  • Create states (Idle, Walk, Run, Jump, Fall) in ABP → AnimGraph
  • Define Transition Rules between states (bool conditions)
  • Use Blend Space inside states for smooth locomotion
  • Cached Pose — Save a pose to reuse in multiple branches
  • Layered Blend per Bone — Upper/lower body split
  • Slot Node — Play Montages on top of state machine
  • Access variables via Try Get Pawn Owner → Cast
⚡ Physics & Collision

Chaos Physics UE5

  • Chaos is UE5's physics engine (replaced PhysX)
  • Rigid Body simulation, constraints, joints
  • Chaos Destruction — Fracture meshes for destructible environments
  • Chaos Cloth — Cloth simulation on skeletal meshes
  • Chaos Vehicles — Vehicle physics model
  • Physics Assets — per-bone collision for skeletal meshes (ragdoll)

Collision & Traces

  • Collision Channels — WorldStatic, WorldDynamic, Pawn, PhysicsBody, etc.
  • Collision Presets — BlockAll, OverlapAll, NoCollision, Custom
  • Object vs Trace channels — Object = what I am; Trace = what I look for
  • Line Trace — Raycast (single or multi hit)
  • Shape Trace — Sweep sphere / box / capsule
  • Overlap — Test shape for overlapping actors
  • OnComponentBeginOverlap / OnComponentHit — Event delegates
  • Always use Collision Complexity: Simple for gameplay, Complex for traces when needed

⇄ Networking & Replication

Replication Basics

  • UE uses server-authoritative model
  • bReplicates = true on Actor to enable replication
  • UPROPERTY(Replicated) — Auto-sync variable to clients
  • ReplicatedUsing = OnRep_Func — Callback when value changes on client
  • RPCs: Server (client → server), Client (server → client), NetMulticast (server → all)
  • UFUNCTION(Server, Reliable) — Guaranteed delivery server RPC
  • UFUNCTION(Client, Unreliable) — Fire-and-forget client RPC
  • Relevancy — Actors only replicate to nearby clients (NetCullDistance)
  • Network Role: Authority (server), AutonomousProxy (owning client), SimulatedProxy (other clients)

Testing Multiplayer

  • PIE Multiplayer: Play → Number of Players = 2+
  • Net Mode dropdown: Play As Listen Server / Client
  • Use HasAuthority() to check if running on server
  • Use IsLocallyControlled() for owning player checks
  • GameState & PlayerState replicate automatically
  • GameMode runs only on server
🌍 World Partition & Streaming UE5

World Partition

  • Replaces sub-level streaming with automatic grid-based loading
  • One Persistent Level — actors auto-assigned to grid cells
  • HLOD (Hierarchical LOD) — Auto-generated imposters for distant cells
  • Data Layers — Tag actors for conditional loading (day/night, quest states)
  • Supports One File Per Actor (OFPA) — better source control, less merge conflicts
  • Streaming Sources — Define what loads around player
  • Enable: World Settings → World Partition → Enable
  • Editor: only loads cells near camera (saves memory for huge worlds)
🌲 PCG (Procedural Content Generation) UE5.3+

PCG Framework

  • PCG Graph — Node-based procedural placement system
  • Scatter foliage, props, entire biomes based on rules
  • Surface Sampler — Generate points on landscape or meshes
  • Density Filter — Control point distribution
  • Spline-based — Use splines to define roads, rivers, boundaries
  • Attribute-driven — Filter/transform points by slope, height, biome tag
  • Deterministic by default (seed-based)
  • Can combine with World Partition for huge worlds
📊 Optimization & Profiling

Profiling Tools

  • stat fps — Frame rate & frame time
  • stat unit — Game, Draw, GPU, RHI thread timings
  • stat unitgraph — Real-time graph overlay
  • stat gpu — Per-pass GPU cost
  • stat scenerendering — Draw call counts
  • stat memory — Memory usage overview
  • profilegpu — Single-frame GPU capture
  • Unreal Insights — Trace-based profiler (CPU, GPU, memory, loading)
  • RenderDoc / PIX / NSight — GPU capture tools
  • Session Frontend → Profiler for CPU traces

Performance Tips

  • Use Nanite for high-poly static meshes (no manual LOD)
  • Use Lumen in Software mode for wider GPU support
  • Disable Tick on actors that don't need per-frame updates
  • Use Timers instead of Tick for periodic logic
  • Pool spawned actors (projectiles, effects) — avoid Spawn/Destroy churn
  • Reduce Draw Calls: merge meshes, use instancing, HISMs
  • Use LODs for non-Nanite meshes and Skeletal Meshes
  • Texture streaming: don't load max res for everything
  • Cull: r.SetNearClipPlane, occlusion settings, per-actor render distance
  • Limit Translucent & Overdraw (esp. particles)
  • Use Significance Manager for adaptive quality on distant AI/effects
  • Compress textures: BC7 (quality), BC5 (normal maps), BC1 (rough/metal)
📦 Packaging & Shipping

Build & Package

  • Development Build — Debug symbols, console commands (for internal testing)
  • Shipping Build — Optimised, no console, no editor features (final release)
  • Test Build — Like Shipping but keeps console for QA
  • Package: File → Package Project → target platform
  • Cook content separately: Project Launcher for custom cook profiles
  • Set Maps to Include in Project Settings → Packaging
  • Exclude editor-only content & unused plugins to reduce build size
  • Use Pak file encryption to protect assets
  • Steam: Steamworks SDK plugin, configure App ID, upload via SteamPipe

Platform Notes

  • Windows — DX12 default; DX11 fallback. Nanite/Lumen require DX12
  • Linux — Vulkan renderer
  • Console — Requires dev kits & NDA platform SDKs
  • Mobile — Vulkan (Android), Metal (iOS). No Nanite/Lumen
  • Set Target Hardware profile (Desktop, Mobile) in Project Settings
