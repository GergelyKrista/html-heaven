00

The Mental Model Shift

Frontend is not a weaker backend. It is a different discipline with inverted priorities — you are now writing for humans who scroll for four seconds before they decide.

On the backend you optimise for correctness, throughput, and uptime. Invisible success. On a game promo site you optimise for one emotion in under four seconds — "I want to play that."

Everything in this manual serves that one job. If it doesn't, cut it. There is no feature so clever it survives a bad hero section.

Two mental flips that will save you two weeks:

1. Design is a constraint problem, not a palette problem. You don't start with a colour picker. You start with: "what's the one thing a visitor must remember after leaving?" Then every type size, every motion curve, every bit of whitespace is in service of that.

2. The browser is your production environment. DevTools is your REPL. You will spend 60% of your time nudging values by 2px and 0.05s until something clicks. This is not procrastination. This is the work.

A game promo site has one job: make the viewer feel something before they read anything. — Field Manual, page 1
Rule 01
One Hero

One headline, one image, one CTA. If you have two, you have none.

Rule 02
Dark First

Games are cinematic. Dark backgrounds let art, light, and motion do the work.

Rule 03
Ship Edges

Full-bleed media, grain, scanlines, asymmetry. Safe centred boxes read as templates.

Rule 04
Respect Eyes

Every effect has an off-switch: prefers-reduced-motion. Non-negotiable.

Stack & Tooling

Pick boring tools. You want every decision you make to be visible on the page, not hidden in config.

02

Typography, Or: Why Your Arial Page Feels Like a TPS Report

Type is 80% of the perceived quality of your site. The correct font is not the font you know — it is the font nobody else is using this quarter.

Type-setting is how websites communicate before words are read. A wall of 16px Inter reads as "documentation." A condensed display face at 140px reads as "event." Pick on purpose.

The working pattern for a game promo: a hard display face (condensed, heavy, uppercase-friendly) + a refined body face + an editorial italic serif for pull quotes, release dates, and credits. Three fonts is a trio; four is a band with tension.

/* Three moves that instantly elevate any headline */
.title{
  font-family: "Bebas Neue", Impact, sans-serif;
  font-size: clamp(58px, 11.5vw, 184px);  /* fluid, not stepped */
  line-height: .88;       /* tight — display type breathes from size, not leading */
  letter-spacing: -.01em; /* optical correction for large caps */
  text-wrap: balance;   /* modern browsers balance ragged lines for you */
}
Type sets the stage before the reader reads. Get it wrong and the best copy in the world sounds like support documentation.
03

Color & Atmosphere

You are not decorating. You are lighting a scene. Your palette is 70% background, 25% ink, 5% signal — and that 5% is doing all the work.

Most bad sites fail here by distributing colour evenly. Evenly distributed is noise. Pick one dominant, one ink, and one signal colour that owns every CTA. A second accent only if the first needs breathing room.

For games: a near-black background with one punchy hue does more work than any gradient you'll construct. Your game key-art is the hero — your palette frames it.

#0A0908bg · 70%
#FAF4E8ink · 25%
#E63946signal · 5%
#F4A261warm accent
#A8DADCcold accent
#D4FF3Ahighlight
/* Put every colour behind a token. Change a game's mood in one place. */
:root{
  --bg:       #0a0908;   /* dominant */
  --ink:      #faf4e8;   /* body + headings */
  --ink-mute: #a89f90;   /* secondary text */
  --signal:   #e63946;   /* CTAs, focus rings, accents */
  --rule:     #2a2621;   /* borders — never pure black */
}

/* Use OKLCH when you need accessible-at-any-hue variants */
.cta{ background: oklch(62% .22 26); }
.cta:hover{ background: oklch(70% .22 26); }

The Hero Section Is The Whole Game

60% of visitors never scroll. Treat the first viewport like a billboard, not a table of contents.

Anatomy of a hero that sells a game: eyebrow (tiny context, mono, uppercase) → title (massive, one line if possible) → one-sentence promise → one primary CTA + one ghost CTA. A background that breathes — grain, scanlines, a hero plate of key-art, a gradient that mimics light. Nothing else.

05

Motion With Restraint

Motion is seasoning. Excellent sites use it on three moments a page — a page-in reveal, a hover on CTAs, and one scroll-triggered set piece. That's it.

The three motion patterns you'll actually ship:

1. Staggered page-in. Eyebrow → title → lede → CTAs rise one after the other in 80ms offsets. 800ms total. Creates the feeling of a room being lit.

2. CTA micro-interaction. Button nudges 2px up-and-left, drops a hard shadow on hover. The arrow slides 3px right. 2px, not 12px. Restraint is the signal.

3. Scroll-triggered reveal. IntersectionObserver flags sections as they enter the viewport. Nothing moves in parallax — that ship sailed around 2019.

/* Staggered rise — pure CSS, no library */
@keyframes rise{
  from{ opacity:0; transform:translateY(20px); }
  to  { opacity:1; transform:none; }
}
.reveal.in   { animation: rise .8s cubic-bezier(.2,.7,.2,1) forwards; }
.reveal.d1.in{ animation-delay: .08s; }
.reveal.d2.in{ animation-delay: .16s; }

/* Non-negotiable: respect the user's system setting */
@media (prefers-reduced-motion: reduce){
  *{ animation-duration:.001ms !important; transition-duration:.001ms !important; }
}
// Scroll-in reveal — 10 lines, zero dependencies
const io = new IntersectionObserver((entries) => {
  entries.forEach(e => {
    if (e.isIntersecting) {
      e.target.classList.add('in');
      io.unobserve(e.target); // fire once, forget
    }
  });
}, { threshold: 0.12 });

document.querySelectorAll('.reveal').forEach(el => io.observe(el));
If you can't explain why an animation exists in one sentence, delete it. — Every senior designer, quietly, for 10 years
06

Layout & Composition

Three layout moves cover 95% of a promo site. Know them cold.

1. Fluid scale with clamp(). Every font-size, padding, and gap uses clamp(min, fluid, max). You write breakpoints only for genuine layout changes — not for "shrink the text."

2. 12-col grid is optional. Most of your page wants an asymmetric 2-col (60/40 or 70/30). A CSS Grid template with named areas beats any framework's col system.

3. Edges over cards. Full-bleed imagery, thin rules, generous inline padding. Drop-shadowed rounded cards read as dashboard — you are not a dashboard.

/* Fluid type scale you'll use on every section */
:root{
  --step-0: clamp(14px, .88vw + 10px, 17px);
  --step-1: clamp(18px, 1.1vw + 14px, 22px);
  --step-2: clamp(24px, 1.6vw + 18px, 32px);
  --step-3: clamp(36px, 3vw + 24px, 56px);
  --step-4: clamp(58px, 11vw + 20px, 184px);
}

/* Asymmetric hero grid — not 12-col, not centred */
.hero-grid{
  display: grid;
  grid-template-columns: 1.2fr .8fr;
  gap: clamp(24px, 4vw, 64px);
  align-items: end;
}
07

The Contact Form

A promo site's contact form is a press / partnerships / support triage, not a customer-service ticket portal. Ask for three things, not twelve.

Good form design on a game site means: visible labels (never placeholder-as-label), big input targets (48px min height on mobile), a focus state that actually shouts, and a Turnstile CAPTCHA instead of reCAPTCHA. Autofocus on load is a hostile act; don't.

Protected by Turnstile · No tracking cookies 
// Cloudflare Worker — contact form handler (complete, ~30 lines)
export default {
  async fetch(req, env) {
    if (req.method !== 'POST') return new Response('nope', { status: 405 });

    const data = await req.json();
    const { name, email, topic, message, token } = data;

    // 1. Verify Turnstile — bot-filter at the edge
    const verify = await fetch('https://challenges.cloudflare.com/turnstile/v0/siteverify', {
      method: 'POST',
      body: new URLSearchParams({ secret: env.TURNSTILE_SECRET, response: token })
    }).then(r => r.json());
    if (!verify.success) return new Response('bot', { status: 403 });

    // 2. Basic validation — never trust the client
    if (!email?.includes('@') || !message || message.length > 4000)
      return new Response('invalid', { status: 400 });

    // 3. Send via Resend (or store in D1, or forward to Slack)
    await fetch('https://api.resend.com/emails', {
      method: 'POST',
      headers: { 'Authorization': `Bearer ${env.RESEND_KEY}`, 'Content-Type': 'application/json' },
      body: JSON.stringify({
        from: 'promo@yourgame.com',
        to: 'team@yourgame.com',
        subject: `[${topic}] ${name}`,
        text: `${email}\n\n${message}`
      })
    });

    return new Response(JSON.stringify({ ok: true }), { headers: { 'content-type': 'application/json' } });
  }
};
08

Performance Is A Design Constraint

A slow site is an ugly site, no matter how good the typography. Budget before you build.

LCP
< 2.0s

Largest Contentful Paint. For games: your hero key-art. Preload it.

CLS
< 0.05

Layout shift kills trust. Always set width/height on media.

INP
< 200ms

Interaction to Next Paint. Avoid heavy JS on the main thread.

JS
< 80KB gz

If you're over this, you're shipping a framework a promo page doesn't need.

<!-- Hero image — the single most important perf optimisation on the page -->
<link rel="preload" as="image"
      href="/hero.avif"
      imagesrcset="/hero-800.avif 800w, /hero-1600.avif 1600w, /hero-2400.avif 2400w"
      imagesizes="100vw">

<!-- Font preload only for the hero display face -->
<link rel="preload" as="font" type="font/woff2"
      href="/fonts/bebas.woff2" crossorigin>

<!-- Every <img> below the fold -->
<img src="/screen.avif" alt="Gameplay: infiltrating the server farm"
     width="1600" height="900" loading="lazy" decoding="async">

Cloudflare-specific wins: turn on Polish (auto WebP/AVIF), Mirage (responsive images), and Early Hints. These are two checkboxes in the dashboard and shave 300–800ms off LCP for free. Use Cache Rules to cache HTML for 60s at the edge — browsers still revalidate but bots get served instantly.

09

Accessibility Is Polish, Not Compliance

The same discipline that makes a site usable with a screen reader makes it more cinematic for everyone.

A game promo site with poor a11y is also a site that feels amateur. Focus rings that match your signal colour, keyboard traps audited out, landmark regions (<header>, <main>, <footer>), contrast ratios that pass AA — these are the same moves that make a site feel meticulous.

The minimum bar: 4.5:1 contrast on body text, 3:1 on large display type, a visible focus ring no matter where you are, and skip links at the top of the DOM.

/* A focus ring that belongs in your design, not Chrome default blue */
:focus-visible{
  outline: 2px solid var(--signal);
  outline-offset: 3px;
}

/* Skip link — visible only on focus */
.skip{
  position: absolute; top: -100px; left: 16px;
  background: var(--signal); color: var(--bg);
  padding: 8px 14px; z-index: 1000;
  transition: top .2s;
}
.skip:focus{ top: 12px; }
